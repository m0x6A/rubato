# Companion: warn when it reads the old workspace.yml

Issue: #132 · Map: `rubato-companion` · Track: small (one part, a new log line, no seam).

ADR 0044 renamed the developer's local config from `workspace.yml` to `local.yml`, and
`RUBATO_WORKSPACE` to `RUBATO_LOCAL`. The skill warns when it reads the old name
(`skills/rubato/scripts/lib/local.ts:115`). The companion falls back to the old name silently
(`crates/rubato-companion/src/kernel/config.rs` `default_path`), so a developer who only runs
the companion never hears about the rename.

## What the change does

- When `rubato-companion run` reads its config by an old name (`RUBATO_WORKSPACE`, a file still
  called `workspace.yml` found by the fallback, or named by `RUBATO_LOCAL` or `--workspace`), it
  logs one `warn` line at start: `<path>: workspace.yml is now local.yml (and RUBATO_WORKSPACE is
  RUBATO_LOCAL); rename it`, the skill's wording without its "after upgrading the companion".
- `--help` names `local.yml` and `$RUBATO_LOCAL` as the defaults, and says the old names are
  still read, with a warning.
- With `local.yml` (or `RUBATO_LOCAL` naming any other file) it logs nothing. Which file is read
  does not change.

## How we'll know it works

- [ ] `kernel::config::tests::a_config_found_by_its_old_name_is_flagged_once_and_local_yml_is_not`:
  `Workspace::path_in` with an empty dir gives `local.yml` and no flag; only `workspace.yml`
  gives it with the flag; both present gives `local.yml` and no flag; `RUBATO_WORKSPACE` is
  flagged; `RUBATO_LOCAL=…/workspace.yml` is flagged; `RUBATO_LOCAL` wins over
  `RUBATO_WORKSPACE`; `Workspace::resolve` flags a `--workspace` path named `workspace.yml`
  and not one named `local.yml`. The warning text matches the skill's.
- [ ] The warning is logged once, at start, after the subscriber is up (`main.rs`, `Cmd::Run`),
  on the companion's stderr: read in review; the start path runs once per process.

## What it must not break

- Which file the companion reads, in the same order (`RUBATO_LOCAL`, `RUBATO_WORKSPACE`,
  `local.yml`, the old `workspace.yml`): the same unit test pins the order, and
  `main.rs` and `default_path` both go through `Workspace::resolve`, so there is one copy of
  the lookup. The Gherkin suites build the `Workspace` in process and stay green.
- `rubato-companion status` and `pair` are unchanged (they do not warn): checked by reading
  `main.rs`.
- Known and kept: the skill tries `local.yml` before `RUBATO_WORKSPACE`
  (`skills/rubato/scripts/lib/local.ts:51-62`), while the companion takes `RUBATO_WORKSPACE`
  first, as it did before. With both present, the companion reads the old file and warns.

## How we'll debug it at 3 am

on the stderr of `rubato-companion run` (the developer's terminal or service journal). The

seam, so there is no O-row.
