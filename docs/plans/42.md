# Server: the database fallback keeps the stored map time and counts one failure per reload

Issue: #42 · Track: small · Branch: `issue/42-map-fallback-age`

## 1. Problem

In `crates/rubato-server/src/map/load.rs` (`reload`), when the GitHub fetch fails and no map is
in memory, the server falls back to the copy in `map_cache` but builds it with
`loaded_at: Utc::now()`, writes that time back to the row, and records it on
`rubato.map.loaded_at`. The "Map age" panel from #31 then shows a fresh map although nothing was
fetched. On the same path a stored copy that does not parse (or does not validate) adds a second
`rubato.map.load_failures` to the one the fetch already added.

`warm` runs first at startup and already uses the stored time, so this path is reached only when
the database had no map at startup (or `warm` failed) and one was stored since, or when the map
in memory was never set.

**Acceptance criteria** (from the issue)

- [x] **AC1** — the database fallback reports the stored load time, not the time of the reload.
- [x] **AC2** — one reload counts at most one `rubato.map.load_failures`.

Prior art: plan `docs/plans/31.md` (the gauge, the panel, the failure counts at each site).

Track: small. `map_cache.loaded_at` already exists (`migrations/0001_init.sql`, `map/store.rs`),
so no migration; one function in one slice; no protocol, wire, consumer or auth change.

## 2. Spec

### 2.1 What the change does

- **S1** — When a reload falls back to the database copy, the map in use and `rubato.map.loaded_at` carry the `loaded_at` stored with that copy, and the row is not rewritten. A later successful fetch stores and records a fresh time as before. (AC1)
- **S2** — When the fetch fails and the stored copy does not parse or validate, the reload returns the parse or validation error and the counter has gone up by one (for the fetch), not two. A file-mode load or a fetched map that fails to parse or validate is still counted once, as before. (AC2)
- **S3** — The fallback's warning line names the stored time: `warn!(error, loaded_at, "map fetch failed; using the database copy {version}")`.

| # | Must keep working | Guarded by |
|---|---|---|
| N1 | A fetched map is stored and recorded with the time of the fetch | existing `loaded_at_follows_loads_and_survives_failures` (a) |
| N2 | A failed fetch with a map in memory keeps that map and its time, counted once | existing `loaded_at_follows_loads_and_survives_failures` (b) |
| N3 | `warm` records the stored time | existing `loaded_at_follows_loads_and_survives_failures` (c) |
| N4 | File mode counts read, parse and validation failures once each | existing `loaded_at_follows_loads_and_survives_failures` (d), `invalid_flows_keep_the_previous_map` |

|---|---|---|---|---|
| O1 | GitHub is unreachable and the server runs on the database copy | "Map age" grows from the stored time (yellow at 900 s, red at 1800 s); `rubato_map_load_failures_total` rises one per reload on the "Map" panel | `warn!("map fetch failed; using the database copy …")` with `loaded_at` and the error | the server never fetched this map in this process · fix GitHub access or the map ref, then `POST /api/map/reload` |

## 3. Where it changes

- `rubato-server` — `src/map/load.rs`: `reload` carries the stored time on the fallback and skips the write-back; a shared `parse(app, yaml, count)` replaces the two copies of parse-and-validate, counting only when the reload has not counted already. Two new tests.

## 4. Caveats triage

- Observability: makes "Map age" honest on the fallback (O1) and the failure counter one per reload (O2). No new name, panel or alert.
- Idempotency: repeated fallbacks leave the row as it was; the in-memory map then short-circuits later failures (N2).
- Derived not stored (project): the stored time is the fetch time, now never overwritten by a non-fetch.
- n/a: Boundaries, Concurrency (the map lock is used as before), Schema change, Contract compatibility, Authorisation, Cost, Telemetry names, Check reports its count, Own tmux only, Log level — one function in one slice.
