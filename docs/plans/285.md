# An empty traffic report says so, not that the map matches

On the deploy, 2026-11-18, a traffic source recovered with `edges=0` and the Traffic lens said
"Map versus territory (0): The observed system matches the map." Nothing had been observed, so
nothing had been compared. A person setting up a source could not tell "connected, no data"
from "connected, all as declared".

## What the change does

- When a fresh report holds no calls, no services and nothing dismissed, the map-versus-territory
  list reads "(nothing observed)" in its summary and says the source answered with no calls
  between services in the window, and that nothing was compared with the map.
- Configure workspace says "Connected, but the source returned no calls between services" on
  the status line, not "Working".
- A report with any call, any service (matched, ghost or without a namespace) or any dismissal
  reads as before.

## How we'll know it works

- [ ] `web/src/features/map/territory.test.tsx`: one empty report, and three reports with
  something in them that must still say the observed system matches the map; prints the count.
- [ ] `web/src/features/settings/settings.test.tsx`: the status sentence for an empty report.
- [ ] `web/e2e/map.spec.ts`, citing `@map.empty-report-says-so`.

## What it must not break

- The server's derivation, findings and the `ObservedTraffic` wire type: untouched.
- Unknown is still never drawn as quiet: `unknown offers nothing (ADR 0039)` in
  `territory.test.tsx` stays green, and a stale or failing source shows no list at all.
- The ghost and dismissal flows: `@map.ghosts-and-discrepancies`, `@map.dismiss-discrepancy`.

## How we'll debug it at 3 am

See the O-row. The server already logs `traffic source recovered` with `edges`; `edges=0` is
the line that matches what the page now says.
