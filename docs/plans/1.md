# Task 1: rubato-protocol

Task 1 of `docs/plans/v0.md` §5. The crate is the contract between companion, server and web:
serde types, no I/O, no async runtime. Everything else in v0 depends on it.

## Affected parts

| Node | Status | What changes | Seams |
| --- | --- | --- | --- |
| rubato-protocol | new | Cargo workspace; `IssueRef`, `MapRef`, `IssuePin`, `SystemMap`, `Plan`, `LaunchCommand`, `LaunchResult`, `HookEvent`, `SessionState`, `Heartbeat`, `CapHit`, `StaleSession`, `PullRequestState`, `DecisionRecord`, `Progress` and the pure `derive_progress`, `CompanionEnvelope`/`ServerEnvelope`, `otel.rs`, `limits.rs`; JSON Schema export to `schema/protocol/`; fixtures | companion-server, web-server |

## O-rows

| Seam | Breaks like | Signal | Panel | Owner |
| --- | --- | --- | --- | --- |
| companion-server | a type changes and one side still sends the old shape | counter `rubato.events.dropped` (`rubato.reason` = schema) on the server; the snapshot test and the fixture replay fail in CI before it ships | Companions · Events dropped | rubato-server |
| web-server | generated TypeScript drifts from the schema | CI diff of `web/src/protocol.ts` against `schema/protocol/`; gauge `rubato.ws.clients` dropping to zero after a deploy | Web clients | rubato-server |
