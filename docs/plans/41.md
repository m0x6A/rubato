# Telemetry that is set in code but asserted by no test

Issue: #41 · Track: small · Branch: `issue/41-telemetry-tests`

## 1. Problem

Three signals are emitted, and no test would notice if one went away (found reviewing #26 and #29):

- `rubato.events.dropped{rubato.reason="replay"}` in `on_replay` (`crates/rubato-server/src/companion_link/ws.rs:141-151`): the warning is asserted, the counter increment is not.
- The error status on the `rubato.team_poll` span when `tmux-ide team --json` fails (`crates/rubato-companion/src/sessions/tasks.rs:124-126`): the `warn!` is asserted, the span fields are not.
- The promtool case for #26 S5 (`observability/alerts/tests/rubato.test.yml`, "A turn ends and the hooks stop with it") passes by the shape of the existing rule and was never seen failing.

**Acceptance criteria** (from the issue and AGENTS.md "every check has a test that makes it fail on purpose")

- [x] **AC1** — a test fails when the `replay` drop is no longer counted.
- [x] **AC2** — a test fails when a failed team poll no longer marks its span as an error.
- [x] **AC3** — the S5 promtool case is seen failing against a broken rule, and that stays checked in CI.

## 2. Spec

### 2.1 What the change does

No production behaviour changes. Tests and one CI step only.

- **S1** — When the server meets a replayed `Hello`, the existing unit test reads the exported data points (in-memory reader from #31) and requires exactly one `rubato.events.dropped` point, value 1, `rubato.reason = replay`; for a replayed heartbeat it requires none. (AC1)
- **S2** — When a team poll fails, the new unit test requires the `rubato.team_poll` span to carry `otel.status_code = ERROR` and a status description with the command's error; a successful poll's span carries no status. The companion's test capture layer gains span capture (`capture::spans()`): span name, fields at open and every later `record`. (AC2)
- **S3** — When CI runs the alert-rule step, `pnpm observability:rules` copies the rules, applies each mutant (for S5: drop `> 0` from the working side of `SessionWorkingNoHooks`), runs `promtool test rules`, and requires a failure at exactly the case written for it (`alertname: SessionWorkingNoHooks, time: 10m`) and nowhere else; it prints `promtool caught N/N rule mutants`, and fails when promtool is missing. (AC3)

| S2, AC2 | `sessions::tasks::tests::a_failing_team_poll_marks_its_span_as_an_error`. Seen failing: with `span.record("otel.status_code", "ERROR")` removed it fails at the status assertion (left `None`) | unit |

## 4. Caveats triage

- Check reports its count (project): `rules.test.ts` prints `promtool caught N/N rule mutants`, and its own must-fail cases are the mutants plus the missing-promtool path.
- Telemetry names (project): no name changes; the tests use `metric::EVENTS_DROPPED`, `attr::DROP_REASON` and `span::TEAM_POLL` from `otel.rs`.
- Testability: span capture records `otel.status_code`, the field `tracing-opentelemetry` maps to the exported status. It does not run the OpenTelemetry layer itself (A1).
- Concurrency: the span sink is per thread like the event sink; `record` calls find their sink through the span's extensions, so a record from another thread lands in the right test.
- n/a: Boundaries, Schema change, Contract compatibility, Authorisation, Cost, Derived not stored, Own tmux only, Log level: tests and CI only.

## 7. Decisions

- **D1** — the promtool mutants run as their own script in the CI step that installs promtool · because `observability:test` also runs in the publish workflow, which has no promtool, and a test that skips itself when promtool is missing would be silent · rejected: adding it to `observability:test` with a skip.
- **D2** — mutate the rule, not the test input · because the S5 case's input already records working = 0; what it can catch is a rule that no longer needs working above zero · rejected: changing the input to keep working at 1 (that tests the binaries' zero, which `counts_include_every_status` and the server's `a_snapshot_without_a_working_session_records_working_zero` already prove).
