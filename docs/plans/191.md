# Identity cache survives a symlinked cwd

`sessions::identity::tests::a_checkout_moves_a_session_onto_its_issue_and_an_unchanged_head_costs_no_git`
fails on every run on macOS. The cause is not mtime, APFS or the git version (2.54.0, Apple
Git-157). It is a path through a symlink. The test's cwd is a tempdir under `/var/folders/…`,
and `/var` is a symlink to `/private/var`. `git rev-parse --show-toplevel` returns the resolved
`/private/var/folders/…` as the worktree, so `recheck`'s "cwd left its worktree" test
(`crates/rubato-companion/src/sessions/identity.rs:43`, a plain `Path::starts_with`) is true on
every poll, and the companion runs `identify` again each time: four git processes per session per
poll. CI is green because `/tmp` on Linux is not a symlink. The same cost hits production
whenever a session's cwd and its worktree are spelled through different symlinks, for example a
launch worktree under a symlinked root (the launch entry keeps the configured path,
`launch/apply.rs:98`, while tmux reports the resolved pane cwd). The fix is in production code:
when the plain prefix test fails, compare the resolved paths before treating the cwd as moved.

## What the change does

- A session whose cwd reaches its worktree through a symlink is not read again from git while its `HEAD` is unchanged.
- A session whose cwd really left its worktree is still read again on the next poll, as today.
- The flaky `kernel::tmux::tests::a_hung_tmux_is_an_error_not_an_empty_server` stops failing under load. Its stand-in for "no server" (`exit 1`) also ran under the 300 ms deadline meant for the hung stand-in, so a slow fork on a loaded machine turned it into a timeout. It now gets the normal deadline. This is test code only.

## How we'll know it works

- [ ] New test `a_cwd_through_a_symlink_costs_no_git_while_head_is_unchanged` (cwd is a symlink to the repo) fails on Linux and macOS before the fix and passes after it.
- [ ] The existing `a_checkout_moves_a_session_onto_its_issue_and_an_unchanged_head_costs_no_git` passes on macOS.
- [ ] New test `a_cwd_that_left_its_worktree_is_read_again` (the cwd moves to a second repo) passes before and after the fix.
- [ ] `a_hung_tmux_is_an_error_not_an_empty_server` passes 20 runs in a row while another `cargo build` runs.

## What it must not break

- A checkout still moves a discovered session onto its new issue (`a_checkout_moves_a_session_onto_its_issue_and_an_unchanged_head_costs_no_git`).
- A launched session keeps its issue and reports drift (`a_launched_session_keeps_its_issue_and_reports_drift`).
- A hung tmux is still an error (`a_hung_tmux_is_an_error_not_an_empty_server`, the 300 ms deadline stays for the hung stand-in).
- The companion's Gherkin suite and `cargo test -p rubato-companion`.

## How we'll debug it at 3 am

See the O-rows. No new log line. The companion's `identity changed` info line (`identity.rs:116`) still shows each re-read that changes a branch. The `rubato.team_poll` span's duration shows a poll that runs git for every session again.
