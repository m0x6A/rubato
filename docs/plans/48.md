## 0. Spec at a glance

- **Does:** the map explains the system and can be worked on: a part or seam says what it is, what flows in and out and what touches it (S26); all open issues are listed and pinned by drag (S1 to S5); parts move in one shared layout (S6, S7); data and control flows are drawn (S8, S9); a plan shows on the map with its own flows (S10 to S12); companions are lanes with a queue you start from (S13 to S17); the map is edited as a shared draft proposed as a pull request (S18 to S23, S25); the server is a GitHub App and its installation is the team (S24).
- **We'll know it works when:** the tests named in design §2.2 pass (Rust unit and integration, Vitest for pure functions and standalone components, Playwright for rendered edges and real drags) and the six e2e journeys in §8 below pass on the local-git harness.
- **Must not break:** N1 to N21: launch only on your own companion, derived progress, old maps and plans, the per-issue poll order and budget, routes, slice rules, additive wire schemas, existing e2e, pairing and unpin screens, an App-less server, repos outside the installation.
- **Debug at 3 am:** O1 backlog stale → "Backlog age"; O3 refused writes → "Web writes rejected"; O4 fan-out → "Layout writes", "Events dropped"; O5 bad map flows → "Map age"; O6 bad plan flows → "Plan checks"; O7, O8 proposals → "Map proposals", "Map proposal age"; O9, O11 queue → "Queue depth"; O12 to O14 App and team → `rubato.web.rejected`, `rubato.github.repos_uncovered`, the start-up check; O10 migration → fail-fast at start.
